# Watch 刷新握手测试方案

## 一、测试策略

纯状态与请求协议单测优先；可控传输集成测试覆盖真实适配调用模式；真机验证独立记录。使用合成快照，不抓取健康缓存。已有 SnapshotReceiver、清除与版本校验测试作为回归资产；开始实现时核对函数名映射，不虚构RED或设备验收。

## 二、详细测试案例

| TC ID | Spec | 优先级 | GIVEN / WHEN | THEN | 当前状态 |
|---|---|---|---|---|---|
| **ID** | TC-WRH-001 | SC-001 / P0：不可达/激活失败，请求刷新→明确连接原因，不报告收到数据 | 待验证 |
| **ID** | TC-WRH-002 | SC-002 / P0：已有快照，手机收到请求→先交付缓存再刷新，接收保存后才成功 | 待验证 |
| **ID** | TC-WRH-003 | SC-003 / P0：无快照、未连接健康、刷新失败→返回各自原因，不交付演示 | 待验证 |
| **ID** | TC-WRH-004 | SC-004 / P0：旧手机无回执，重复点击与迟到结果→15秒超时、合并请求、隔离迟到结果；context兼容 | 待验证 |
| **ID** | TC-WRH-005 | SC-005 / P0：清除、旧revision、新producer、落盘错误→统一校验，不复活旧数据或虚报保存成功 | 既有回归+待补集成 |

## 三、测试执行矩阵

| 功能 | 单元 | 集成 | 真机 |
|---|---|---|---|
| 请求与状态 | 可控时钟及请求ID | mock传输发送/回复/错误 | 断连及可达状态 |
| 快照交付 | 合成快照接收规则 | 两种通道与手机刷新失败 | 手机已有数据→Watch同revision |
| 缓存持久化 | 原子保存与失败 | 重启恢复 | 安装后重新打开 |

## 四、回归风险矩阵

| 区域 | 风险 | 保护 |
|---|---|---|
| 清除与换手机 | 高 | 第五项用例与既有接收器测试 |
| 旧版本兼容 | 高 | 第四项用例，不强依赖旧手机回执 |
| 更新手机签名 | 高 | 单独确认部署方案，不覆盖既有包 |
| 评分与健康读取 | 中 | 不改公式、不扩大读取；全量check |

## 五、建议补充顺序

先建立第一/第四项可失败信号，再第二/第三/第五项；运行scripts/check.sh、scripts/build-apple.sh和三路只读审查。最后经确认解决签名后做双端真机同步验收。构建成功不等于设备同步成功。
