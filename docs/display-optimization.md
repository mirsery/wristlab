# 功能展示优化建议

状态：本文初稿为信息架构建议；随后活动页整合、趋势三分区均在独立change完成Gate1/2并实现，**交互体验仍待验收**。统一状态条仍是建议，不是已实施界面；下面的结构观察描述优化前源码，不代表已经进行手机任务测试。

## 核心判断

现有五Tab已解决所有内容堆在一个页面的问题；下一步不宜继续增加Tab，而是让每页回答一个问题。产品需要两条并行主线：**状态理解**（今天→睡眠/趋势）与**行动回顾**（计划→执行→趋势），避免把健康分数、运动时长和减重结果混成一个“达标”。

观察依据：`Apps/iOS/PhoneDashboardView.swift` 的 todayContent、activityContent、trendsContent、accountContent，以及 `Apps/iOS/AutomaticMovementViews.swift`、`Apps/iOS/PlanningViews.swift`。目前今天先放计划再放准备度；活动首屏同时有自动周计划与手动计划；趋势先后堆放体重、运动周回顾、日内节奏、指标图、健康周回顾与心情；我的又提供多处计划入口。这些是结构上的重复与密度风险，尚未用手机任务测试量化。

## 推荐的信息层级

| 页签 | 只回答一个主问题 | 首屏优先 | 进入二级详情 |
| --- | --- | --- | --- |
| 今天 | 我现在是什么状态，今天安排是什么？ | 精简数据状态条；准备度主卡＋电量/压力；一张今日行动摘要 | 基线、覆盖度、原因、睡眠/活动详情 |
| 睡眠 | 昨晚睡得怎样，与平时有何不同？ | 日期与来源；主睡眠时长/阶段；一条事实性差异 | 小睡、睡眠债、规律性、来源规则 |
| 活动 | 今天做什么，这周进展如何？ | 今日安排与执行按钮；已记录/目标分钟；紧凑周历 | 周草案编辑、全部运动、负荷与区间说明 |
| 趋势 | 一段时间里有什么变化？ | 健康 / 运动 / 体重三个页内分段，共用清晰周期 | 记录明细、基线方法、历史回顾、心情并列 |
| 我的 | 如何管理数据和个人偏好？ | 健康连接状态；目标/计划管理；数据与隐私 | 来源、时区、通知、清除、关于与模型 |

“健康 / 运动 / 体重”页内分区已实现，保留五Tab与主导航名称。健康和运动各自7/30日，体重仍为原分析周，周期不混用。趋势验证与未验范围见[趋势报告](../.stdd/changes/2026-10-22-trends-page-sections/test-report.md)。活动页今日优先、周摘要、管理计划与负荷二级入口已实现，见[活动页报告](../.stdd/changes/2026-10-22-activity-page-hierarchy/test-report.md)。

## P0：先减少干扰，不增加新指标

1. **统一状态条**：真实/演示、更新时间、正在刷新/失败仅占简洁摘要；可展开来源、时区和模型。空值、过期、失败不得只用颜色，也不得把旧报告说成最新。状态条保持普通滚动内容，沿用睡眠页已修复的安全区边界。
2. **活动只留一个主计划入口**：自动与手动是模式，不做两张同等重量的大卡。今日任务卡优先；周历和“管理计划”承接生成/切换。已采纳模式、未来生效日、休息日必须明确；无计划时只给一个“建立计划”主按钮。
3. **今天压缩为两层**：先状态，再行动；不展开整周草案或长说明。不生成无依据的“今天很适合高强度”结论。
4. **解释渐进展开**：卡片保留值、单位、状态和一个关键缺失原因；公式、来源明细、未计入运动列表放详情。不删除数据不足/实验估算标识。

## P1：把目标、执行和结果分开

- **目标**：起始/目标体重（kg）、截止日期、当前状态；到期进入回顾，不画“倒计时施压”。
- **执行**：今日已记录运动分钟 / 已采纳目标；人工确认或休息另列标签。没有健康记录显示“待确认”，不能把人工完成伪装成健康数据已达标。
- **结果**：最新体重与记录日期、具备数据门槛时的周均趋势；缺失日不连假线，不把一天体重波动解释成减脂。
- **周回顾**：计划日、记录匹配、人工完成、休息、待确认清楚区分；提供“查看下一周草案”，不静默加量、不补课。周历大字体下仍可读，详情必须可通过文字进入。

## P2：README与对外展示

- README先功能面板与五个任务入口，再真实截图、运行方式、技术细节；示意图与运行截图独立命名、独立说明。
- 目前旧截图只代表其生成版本，不能证明最新五Tab或自动计划界面。后续取得可核验截图时补“今天 / 活动计划 / 趋势体重”三张手机图，均用明确合成数据，保留生成来源。
- 不在功能总览列未经验证的实时同步、安全训练量、减脂预测或AI建议；不展示真实用户健康资料。

## 建议实施顺序与验收

| 顺序 | 一个独立变更 | 验收要点 |
| --- | --- | --- |
| 1 | 活动首屏＋自动/手动入口整合 | 找到今日任务、查看已记录分钟、完成/休息、进入周草案；已处理历史不变 |
| 2 | 趋势页内分段 | 健康/运动/体重不混淆；切换保留周期与位置；空状态可达 |
| 3 | 统一摘要状态条与详情展开 | 顶部不遮挡；演示/过期/失败仍明显；保留原因和更新时间 |
| 4 | 更新实际截图与README证据 | 可追溯运行版本、合成标记、无真实健康数据，不以概念图替代 |

每步先确认交互设计再实施，不重做评分算法。至少检查：默认与最大辅助字体、窄屏、长中文、空数据/校准/失败/旧数据、滚到顶部/底部、Tab切换后位置、弹窗取消与保存、演示切换、真实手机安全区。拟定易用性目标为用户无需说明找到“今日安排”和“记录体重”，再通过任务测试记录点击数与耗时；当前没有基线数据，不宣称体验已提升某个百分比。
