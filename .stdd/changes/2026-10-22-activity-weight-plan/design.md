# 运动计划与减重目标 — Gate 2 已确认

## Context
用户已确认竞品参考后的两阶段范围。当前五Tab改动尚在本地、Gate3待验收，本轮保留这些编辑，不混记为本轮成果。
specs/001-product.md当前不提供训练处方；specs/005-activity.md参考区间不得视为剩余安全额度。新增行为批准后再同步权威产品/活动/健康同步规格。
现有HealthReport只有实验性状态和负荷；没有体重、饮食或动作组数数据。本轮不宣称有完整教练能力。

## Decisions

### 1. 计划由用户偏好生成，状态只辅助调整
目标：保持活跃、提升体能、辅助减重。配置常做活动、每周具体日期、常规时长、可选轻量活动和时长。所有时长是用户输入，不从分数换算。
计划是用户安排，不是处方。未配置不生成默认训练；当日未安排时显示休息/自由安排，不自动补课。
纯领域规则版本activity-plan-v1，优先级：
1. 暂停计划 → 不推荐，仅可查看历史。
2. 未建立计划/无当天安排 → 显示设置入口/原定休息。
3. 当天已完成或休息 → 展示结果，不追加运动。
4. 当天报告缺失、非当天、过期、校准或准备度不可用 → 显示原定安排+具体数据原因，不输出个性化增减量。
5. 当天准备度可用且显示整数0–32 → 标注“准备度较低，可选择休息或你预设的轻量安排”，保留原计划，需用户自己采纳，未预设轻量方案时只给休息选项。
6. 其他可用准备度 → 展示原定安排和状态解释，不称适合高强度或保证安全，不自动加时。
理由显示报告日期、准备度有效时间/模式/校准原因、规则版本；睡眠和已观测负荷并列作背景，不推断独立病因。
这些是保守产品行为规则，不是经临床验证的训练建议。沿用现有准备度分段是展示锚定，不修改评分模型。
不采用直接将电量或负荷目标映射分钟的方案，现有数据不支持这种换算。

### 2. 周执行与变更
周从分析时区周一00:00开始，按日历处理DST。计划编辑仅影响今天尚未处理项及未来日期；已完成/休息保留原计划快照。
每日状态planned/completed/rested；替换活动不标完成。休息为合法选择，完成率分开列计划次数、完成次数、休息次数，不把休息伪装成完成。
重复完成幂等；撤销操作允许恢复planned。手动完成标记明确，首版不靠稀疏HealthKit记录自动认定完成，避免跨应用运动重复或漏匹配。
跨午夜只按用户选择的计划日标记；不把记录的设备时区静默改成分析时区。

### 3. 减重目标与记录
首个交付切片使用本地手动记录；健康体重只读导入是后续可选切片，需要独立详细选源/删除/授权规格，不在首版静默请求。
目标记录起始体重及日期、目标体重、用户期望截止日期、状态active/paused/archived。值必须有限且大于0，减重目标低于起始值，截止日期晚于开始日期；这些是录入一致性检查，不是健康适宜性判断。
设置期望期限只表达意向，不计算推荐下降速度、预计达标日、每日摄入或热量缺口；不自动选择目标体重，不承诺该目标健康适宜。
没有饮食、年龄/适用人群评估时不做营养处方；儿童、孕哺和临床管理场景不做个性化减重建议，首版不额外收集这些敏感属性。
记录包括稳定ID、kg值、采样时间、录入时间、来源manual；手动记录可编辑和删除，不写入Apple健康。
用户后续明确要求“去除 lb 磅这个显示”：体重趋势、记录/编辑与减重目标全部只显示和录入公斤（kg），移除单位切换；存储继续kg，无数据转换或迁移。
体重日期不得晚于当前时间；同日多次保留明细，趋势先取当日最后采样值，同采样时间按录入时间再ID稳定排序。
周均按有值的日值等权计算，至少3个不同日才给周均，显示N/7；不足时只画记录点。前后周均都满足门槛才给变化，今天所在周标进行中。缺失日不补值，不将单次反弹当成脂肪增加。
差距=最近有效体重减目标体重，目标下方标“已达到设定目标”，无体重时不伪造进度。目标可调整/暂停，历史快照保留；暂停不阻止记体重。

### 4. 本地数据与清除
建议在现有RepositoryState新增带默认空值的PlanningState，与健康状态共用原子提交及文件保护；旧缓存无该字段仍可解码。HealthKit读取和报告重建保留手动计划及体重。
模型位于WristlabCore；HealthKit和文件保护仍在现有适配边界。所有写入经仓库串行事务，成功才发布UI；失败保留旧文件与显示状态。
“清除派生缓存并重算”保留手动计划/体重；“停止读取并清除应用数据”一并删除计划、体重与执行记录，清除文案列明。后续异步刷新不能把已清除数据写回来。
演示使用独立合成PlanningState，禁止写真实存储、发送Watch或Widget，也不将体重加入既有快照。退出演示恢复真实状态且清理演示详情路径。
不新增依赖、账号、网络或健康数据日志。

### 5. 页面
- 今天：原今日状态下增加一条当天安排摘要及跳转。
- 活动：当天安排、可选调整、周安排和完成/换一个/休息操作，下方保留负荷内容。
- 趋势：体重折线、周均及记录天数、目标差距和周执行回顾；明细支持修改删除。
- 我的：建立/编辑/暂停计划，减重目标及记录体重入口；睡眠Tab不变。
复用现有五Tab，不增加第六个Tab；表单可访问，单位清楚，破坏操作需要明确提示。对目标只展示事实，避免失败羞辱或强迫补练。
备选独立计划Tab会挤占五Tab空间且重复活动入口，因此不用。

## Architecture
SwiftUI主题页 → DashboardModel → HealthRepository事务 → RepositoryState.PlanningState。
ActivityPlanRules/WeightTrend为无Apple API的纯领域计算，ActivityPlanRules读取HealthReport投影及固定时钟；视图只显示规则结果。
计划变更与目标记录带revision，保留历史执行快照，过期操作不能覆盖更新事务。

## Risks / Trade-offs
| 风险 | 缓解 |
| --- | --- |
| 建议被误当运动安全保证 | 原定安排、用户采纳、无自动加量或分数换分钟 |
| 期限引导过激目标 | 不推荐速度、无达标预测或自动热量赤字 |
| 体重噪声及稀疏数据 | 日值再周均，至少3日，展示覆盖，不推断脂肪 |
| 缓存升级/清除丢手动数据 | 默认字段解码、原子提交及stop语义回归 |
| 用户误以为自动识别运动 | 首版手动完成清楚标记；导入匹配延后 |
| 范围偏大 | A运动计划→B手动减重追踪；可选健康导入后续另定规格 |
