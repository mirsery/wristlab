# 手机连接反馈与读取生命周期 - 技术设计（Gate 2已确认）

## Context

手机2402已实际安装并可启动，用户仍报连接按钮可点但无反馈，之前刷新已取消。未确定真机停在系统请求、缓存保护还是取消路径；不得认定权限拒绝。Watch开发连接在重启后仍1035，独立阻塞，不以手机问题修复宣称手表可用。

隔离诊断直接编译完整生产DashboardModel，仅替换SDK/同步适配器并把缓存路径定向临时合成目录，不读取健康数据。两个真实模型路径已RED：`python3 work/phone-health-probe/run.py`输出visible_feedback=false、duplicate_blocked=false；带cancellation参数输出caller_cancel_did_not_abort_read=false，均退出1。原文件未改，原始日志保留work/phone-health-probe/。这是控制流缺陷复现，不证明真机系统请求具体停在哪一步。

候选原因排序：1）授权等待阶段没有状态/busy更新，可由挂起合成授权复现；2）视图刷新任务取消直接传入读取，可由已取消调用者复现；3）loadError/repository守卫静默返回，待缓存失败测试核验。真实系统授权是否长时间等待仍未知。排序不等于把某条认定为真机唯一根因。

## Decisions

### 1. 明确连接阶段与可恢复缓存错误

**方案**：点击后在第一个await前占用操作并更新提示，UI显示等待系统请求/读取中，避免重复授权；缓存打开失败时给出保留原文件、解锁后重试提示，用户再点连接会重试打开，不静默跳过。授权完成不表示每类样本可读。

**为什么**：当前connect在authorize前既无反馈也无互斥，loadError守卫无反馈。不能让用户靠重复点击猜测状态。

**备选方案及排除原因**：
- 仅修改按钮文案：无法处理异步操作重入、错误恢复与取消，不采用。
- 强制重新授权或清缓存：无法证明拒绝授权，且违反不清数据边界，不采用。

### 2. 模型持有单个连接/刷新任务，保留显式取消

**方案**：把读取操作交给MainActor模型持有的Task，页面、前台事件、观察与下拉刷新加入当前工作，互斥在读取仓库前建立。不让调用页面的取消自动终止共享读取；保留adapter的取消检查。连接后必须执行本次强制读取，不因普通刷新合并丢失；必要的观察更新最多合并为一次后续刷新，禁止无限失败重试。显式停止/清除会取消当前工作并通过generation/revision拒绝晚结果，不自动恢复已停止读取。

**为什么**：视图生命周期不应拥有用户已发起的整个健康读取，但用户明确停止必须仍有效。模型任务不保证被系统挂起后继续执行，不新增后台能力。

**备选方案及排除原因**：删除Task.checkCancellation会破坏显式停止，增加无用查询；每次事件新开任务会造成重复读取及revision竞争，都不采用。此次不重写仓库或评分引擎。

### 3. 生产控制器测试接缝与同包交付

仅在必要处允许注入缓存文件/适配器，正式默认仍原路径与真实HealthKit。隔离macOS测试宿主编译实际DashboardModel，合成读写器控制授权/查询挂起、失败与取消，空记录与晚回调均不含真实样本；正式App SDK实现继续由双端Apple构建覆盖。真机只记录状态，不导出样本。目标同包手机2403覆盖；Watch源码保留已确认的calendar修复，内嵌包随构建版本一致，但若连不上不重复无效安装，不把内嵌包当手表更新。

实现细化：UNUserNotificationCenter在无App身份的SwiftPM宿主会抛平台异常，故仅注入通知清理动作，生产默认仍原系统调用，合成测试用空动作，不改变通知行为。既有旧运动重读请求也在并发时保留，新增RED确认后修复。晨报等待后补代次/取消检查，防止旧状态覆盖停止。均为已确认生命周期/数据保留边界内细化，非权限或评分设计变更。

2403设备反馈后补漏：用户明确是首页打开的设置弹层中点击无反馈。设置页原状态Text位于长表单最底部，首页进度被sheet遮住，连接/刷新按钮亦未使用busy。这仍属于已确认的连接阶段反馈，不新增读取或权限。S2把实时状态、忙碌指示与禁用规则放在连接按钮同组，保留弹层及原配置输入、不自动关闭设置；合成演示保持不触发真实连接。以生产SettingsView+生产DashboardModel+合成适配器的iOS UI宿主验证点击、等待、读取、空结果/失败和演示边界，手机迭代版本2404。所有状态仍不代表真实HealthKit已可读。

## Architecture

按钮/视图刷新/观察 → DashboardModel单任务与阶段 → 原HealthKitReader只读五类 → 原HealthBatchLoader → 原HealthRepository原子apply → 原报告/同步/状态。

预计影响DashboardModel、PhoneDashboardView、隔离生产控制器回归宿主及check.sh接入；不增加运行依赖、网络、权限或存储迁移。

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 晚回调复活已停止读取 | 显式取消、generation/revision和停止/清除合成回归 |
| 原因未知而误报已恢复 | 合成控制流、实际安装、真机读取分开记录 |
| 合成SDK替身不能证明真实权限可读 | 不声称真实HealthKit通过，Apple构建加用户状态复验 |
| 模型Task比页面寿命长 | 单任务有明确释放，无无限重试，无新增后台承诺 |
| 缓存损坏无法自动恢复 | 不覆盖/不删除，展示明确恢复失败，保留文件 |
