# Watch日常关怀版 - 已确认设计（代码/模拟器Gate 3已确认，平台待验）

## Context

用户对关怀首页、可解释压力、可选心情、小确幸反馈、日常活动和图表/组件范围回复“开始”，随后强调“各种心情状态压力水平设置图标，避免直接给分数 看不懂”。完整设计展示后用户回复“实现吧”，Gate 2已记录；随后对明确边界回复“确认以上预授权，连续推进”。复杂度12，thorough/full_auto；仅本地编辑测试及模拟器，不提交推送、不操作真机、不开启iCloud、不导出健康数据。Gate 3随后获“确认开始完成吧”实际确认，保留报告披露的平台待验项。

现有依据：specs/001产品、002压力公式、003数据/清除、004睡眠、005运动，以及watch-independent的WI-L/WI-S。WatchReportModel处理独立仓库与所选报告，WatchDisplayStore原子投影给App/组件。当前DisplaySnapshot主动移除贡献、无趋势，手机模式不能凭三项分数生成曲线。日常活动和心情是新增本机能力，不重写已有五类评分读取和手机协议。

## Decisions

### 1. 三个页面：关怀、活动、状态

**方案**：主界面采用可左右切换的三个页面，页内支持Digital Crown/滚动；小屏和辅助字号可进入原生页面选择列表。系统导航栏负责菜单，不覆盖正文，不保留8pt信息墙。默认展示关怀页，原来源/独立连接/刷新/停止清除/组件说明均保留在更多。

| 页面 | 首屏主内容 | 二级内容 |
| --- | --- | --- |
| 关怀 | 一句关怀、图标生理压力、今日步数/活动分钟、可选心情入口 | 数据依据、来源/更新时间、准备度与电量详情 |
| 活动 | 本机今天的步数、锻炼分钟、系统活动圆环 | 各环实际值/目标/暂停/未知、最近7日步数柱状图 |
| 状态 | 生理压力图标+文字、输入质量/情境、日内等级趋势 | 本地当前桶HR与个人基线、HRV参与说明、缺失原因 |

**为什么**：把关怀、生活事实与实验估算分开，不让用户用分数猜含义。图标不单独承担语义，每个图标有短标签及VoiceOver。

**备选**：继续在单页加环/小字会重现拥挤；只换颜色无法解决理解和色觉问题，因此排除。视觉草图采用两种排布供选择，推荐关怀优先；图标是示意，生产使用系统SF Symbols，并验证当前watchOS部署版本。

### 2. 压力是身体估算，心情由用户表达

默认页面、图表轴、组件、VoiceOver不直接报0–100分；内部仍用原模型整数分段，不改变参数或模型版本。事实数值（步、分钟、心率bpm等）保留单位，不一并隐藏。

| 内容 | 内部规则 | 图标语义 / 可见标签 |
| --- | --- | --- |
| 生理压力 | 原0–19 / 20–59 / 60–79 / 80–100 | 叶子“较低” / 平稳波形“常态” / 风“偏高” / 较密波形“较高” |
| 运动情境 | 原metric.mode=activity | 运动图标“运动中”，不呈现“你很紧张” |
| HR-only | 有合法可用值但缺当前HRV | 等级仍可展示，旁注“仅心率估算” |
| 校准/缺失/过期/错误 | 沿用ComplicationPresentation优先状态 | 沙漏“校准X/14” / 问号“暂无估算” / 时钟“待更新” / 说明“刷新未完成” |
| 准备度 | 原0–32 / 33–66 / 67–100 | 小芽“较低” / 叶子“接近个人常态” / 太阳“较高”，明确是准备度，不是心情 |
| 身体电量 | 原数值及可用状态，无新增分段 | 电池图标与“身体电量估算”，不新造饱满/耗尽阈值；可用时图形反映原值，不印评分 |
| 自报心情 | 用户主动选择，不由传感器计算 | 太阳“开心” / 叶子“平静” / 圆点“一般” / 雨云“低落” / 风“紧绷” |

优先拒绝演示/清除/无效来源，叠加过期/必要输入不足，再判断活动情境/HR-only，最后展示等级；无数据不套微笑或“状态很好”。压力沿用HR+可选HRV、睡眠/清醒基线隔离、14有效日及15分钟有效期。缺当前心率不算；单次心率高、疲惫或自报紧绷不直接改变压力数值。身体压力低而用户心情低落时并列两者，不否定用户感受。

本地压力详情显示report.stress.contributions已存在的桶HR与baselineHR，不称实时心率；没有原始HRV值时只说明“本次含HRV/仅心率”，不从z值反推原始HRV。手机快照没有贡献则说明需要打开手机看依据，不能拿手表HR拼手机分数。仍标实验估算、非心理/疾病判断。

### 3. 日常活动独立主动连接，只读真实系统摘要

**方案**：新增Watch专属DailyActivityReader，与五类评分适配器分开。用户点“连接日常活动”后请求读取stepCount与activitySummary；不请求写权限，不新增运动会话、传感器常驻或后台观察。授权请求完成不证明数据可读。步数与活动摘要分开查询，允许一项成功另一项无数据/失败，不阻塞压力与旧报告。

步数使用HealthKit统计查询.cumulativeSum，不把不同来源原始样本或手表与手机合计相加；展示“手表可读健康汇总”，不保证与其他设备同一时刻一致。读取当天截至asOf及此前6个日历日，不延用评分记录150日窗口；有统计结果的0保留，nil未知。七日柱状图缺失留空，过去日与今天进行中分别标记，不凭步数设10000步目标。

Apple活动摘要按其系统日期展示，不强行改成评分的固定分析日。活动页标“手表系统今天”和当前时区；压力图按固定分析时区，差异时分别列明，不合成一个健康总分。系统时区/日期改变时失效旧当日投影并重新查询；心情按提交时系统日记录。

活动环直接使用HKActivitySummary返回值和真实目标：Move按activityMoveMode选择能量(kcal)或活动时间(min)，Exercise用appleExerciseTime和可用exerciseTimeGoal，Stand用appleStandHours和可用standHoursGoal。目标nil/非正不补30分钟或12小时，可展示已记录事实、目标未知，不画完成进度；超目标保留实际值，环图到一圈封顶且可标“已达到设定目标”，不强制追赶。支持watchOS 11+的isPaused；旧系统不猜暂停。暂停时显示“今天按自己的节奏”，不显示失败或补课提示。单位/模式未知时该项明确不可用，不借另一模式。

仅在主动连接、手动刷新、已启用且前台恢复时请求；合并重复操作、取消后拒晚回。无秒级实时/固定刷新承诺，显示readAt/asOf，缓存超过60分钟、位于未来或非当日则不作当前累计/祝贺；旧事实可在详情注明历史时间查看。新一天不沿用昨日圆环或步数。

**备选**：CMPedometer单独计步或HKWorkoutSession会增加另一套来源/运动录制含义，本轮不采用；自行合并样本可能重复统计，故交由HealthKit统计API。

### 4. 一键心情与小确幸，只有主动操作才落盘

心情可跳过，不弹权限、不写HealthKit。五个带标签图标，提交确认后只保留本机当前系统日一条（包含捕获的日期、时区、选择、记录时间和schema）；可改、删，不保留长期历史/连续打卡。不写自由文本、不进入评分、手机、云、组件或日志。页面打开后跨日/换时区/演示切换则拒绝旧提交并提示重新选择。旧日记录不展示，启动/成功写入时清理过期记录，清理失败仍不显示为今天。

关怀文案由Core纯规则生成，固定优先级、无随机奖惩：先无效/过期/待连接的中性说明；再用户当天自报的接纳式回应；再当前有效非运动的偏高/较高生理压力下的可选“如果愿意，给自己片刻停顿”；再真实未暂停且目标已达到的活动事实肯定；否则“按自己的节奏，今天也值得被好好对待”。每次最多一条，不造“恢复很好/情绪稳定”、不从几步路推断健康改善、不承诺缓解效果。

没有完成环不责备、未签到不催；无新推送、震动、医疗告警、补课或自动调目标。自报心情永远不被传感器结果纠正；关怀卡允许收起，本次会话内保持，不做奖励机制。

### 5. 真实图表与克制组件

压力日内图消费当前选中本地报告的5分钟stressTimeline，用固定等级带与时间轴，不显示0–100刻度；相邻有值桶可连接，缺口断开，运动单独图标标识，未知不映射低压力。最多288个当天桶，部分桶/HR-only可辨且不当心理状态。手机模式没有历史，显示“手机快照暂不包含趋势”，不自动切本地、不画平线；本机步数七日图独立标明来源，不与手机压力合成。

保留既有Widget kind与deep link路由，圆形用单图标+短状态，矩形以一个主要状态+来源/更新时间为主，行内/角落用可读短标签，不塞三组小数字。状态总览仍可看三项但均为图标状态；电量不新增等级阈值。新增独立“今日活动”组件以步数/锻炼分钟事实为主，点击进活动页；不展示心情与关怀文本，不伪装完整自定义系统表盘。支持单色、accented/低亮度与减少动态效果，缺失/过期图标优先，不由组件发起健康查询。

### 6. 本机私有状态与单原子展示投影

新CareStateStore保存主动连接标记、最近7日活动汇总与当天心情，放Watch Application Support独立文件，沿用文件保护/排除备份/原子写入；不保存原始样本序列或真实设备ID。schema检查、大小上限、非法值/未来/日期/时区校验，损坏保留文件并明确错误，不替换成演示或0。

WatchDisplayEnvelope新增可选careProjection（旧缓存缺字段为nil），App与Widget仍消费同一个原子文件。所选压力/准备度/电量沿原snapshot，新增本地活动始终有“手表活动”独立标签，不抢报告模式。趋势/依据只在选中本地、source/profile/revision相符时产生，切手机立即失效。心情不写共享投影，仅App从私有store读取。

投影携带生成代次、时间、日/时区、所属报告mode/producer/epoch/sequence/config及最小图表；不改DisplaySnapshot的snapshot-v1手机协议或32KiB限制。Watch展示包仍≤40000bytes，图表太大时仅移除可选趋势并标原因，不能丢失错误/来源/时效字段或悄悄截成连续图。先写文件成功再发布App与reload Widget；失败保留旧包，私有保存成功/投影失败分别说明并可重试。

停止日常活动读取仅取消该reader、清活动缓存，保留心情与评分；“停止手表读取并清除本地数据”在确认中明确包括本地评分、日常活动和心情，先持久停止/清理标记、再取消和清理，失败保持停止并可重试，重启不复活。手机clear只清手机分区，不动这些本机数据。演示使用独立内存状态，不请求额外权限或写任何真实store/Widget。旧producer确认、两份报告隔离和失败恢复语义不变。

## Architecture

```text
原WatchReportModel + 原HealthRepository → 当前所选报告/最小快照
主动DailyActivityReader → 7日统计/活动摘要 → CareStateStore
用户图标选择 → 当天自报心情 → CareStateStore（仅App）
纯Core状态字典/关怀规则/趋势投影 → WatchDisplayEnvelope原子commit
 → Watch三页 + Widget同一已提交投影（不含心情）
```

平台查询、存储与系统调度在Apps；Core仅模型、验证、映射和规则；视图不直接查HealthKit。拟新增/修改：Core的DailyWellbeing模型与Tests；Watch日常reader/协调器/页面/心情表单；Apps/Storage本地care存储及共享投影；Apps/Widgets与组件注册回归；根specs/001/002/003/006、PRIVACY和README在Gate 2后实现前更新。iOS评分读取和云配置不改。

## Risks / Trade-offs

| 风险 | 防护 |
| --- | --- |
| 图标被理解为情绪检测/正常诊断 | 生理压力和自报心情分区，图标+标签，实验说明；真实缺失优先 |
| 手机没有曲线数据 | 显式缺失，不扩协议/不切来源；后续丰富手机快照另立范围 |
| 系统日期和固定分析日不同 | 两处列日期/时区，活动不参加评分，跨日失效 |
| 圆环缺目标/暂停/Move时间模式 | 真实返回值/单位，未知不画比例、暂停不催 |
| 单个查询失败拖垮全部 | 分项状态与独立只读授权，失败保留旧投影并明示时间 |
| 心情泄露/误提交或清除复活 | 本机当天一条、无共享投影，捕获日期/来源，停止标记与代次保护 |
| 图表/组件截断与额外体积 | 有界当天288桶/7日，40KB总限制，辅助字体单列验证 |
