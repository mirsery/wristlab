# iPhone 五 Tab — 技术设计（Gate 2 已确认）

## Context
现有 PhoneDashboardView 在单个 ScrollView 串联所有内容。DashboardModel 持有真实/演示报告与设置；HealthReport 已有睡眠、日内曲线、35日历史及个人基线。
关联权威规格：specs/001-product.md P-001–P-008、specs/004-sleep.md、specs/005-activity.md、specs/003-health-and-sync.md。
本轮只重组手机展示，不修改评分、HealthKit 类型、持久化 schema 或 Watch。

## Decisions
### 1. 五个原生底部 Tab
使用 SwiftUI TabView，顺序为今天、睡眠、活动、趋势、我的，冷启动默认今天。
各 Tab 独立 NavigationStack、路径与滚动位置；当前会话内切换保留状态，冷启动不要求恢复。
选择原生导航是为了系统可访问性及稳定状态；不采用横向顶部页签，避免主题入口随长页滚走。
DashboardModel 继续单实例，由根视图共享；页面切换不调用 start/connect，不重复申请权限或注册观察者。

### 2. 内容分配
| Tab | 主内容 | 详情 |
| --- | --- | --- |
| 今天 | 日期、准备度、电量、压力、主睡眠摘要、今日活动摘要、数据状态 | 三项估算原有依据详情；睡眠/活动摘要切换相应 Tab |
| 睡眠 | 主睡眠阶段、时长、效率、入睡用时、清醒、小睡、债务与规律性 | 复用 SleepDetailView 内容，独立标题与返回行为 |
| 活动 | 输出、已观测负荷、覆盖度、已观测心率区间分钟、参考目标、今日各次运动负荷 | 低覆盖下界说明、目标缺失原因 |
| 趋势 | 一天的节奏、7/30日五类历史、个人基线、周回顾、心情 | 保留现有筛选、曲线断线与心情连接 |
| 我的 | 健康连接/刷新、报告更新时间和来源、校准有效日、现有设置入口 | 复用 SettingsView，包含来源、偏好、晨报、演示及清除 |

今天最多三组内容：核心状态、两个主题摘要、数据状态；不放完整曲线和列表。以内容分组验收，不保证所有字体/屏幕下固定一屏。
睡眠和活动允许主题内滚动；主题页优先展示摘要，再展开说明，避免把整个旧首页搬进每个 Tab。
我的直接承载信息和可达的设置入口；设置可复用 sheet，避免大规模改变原有表单行为。

### 3. 数据充分展示的边界
复用 HealthReport、SleepBreakdown、DayTimeline、LongTrends、MoodOverview 和现有解释模型。
活动 day/workouts 的 LoadSummary 包含负荷、覆盖率和心率区间分钟；workouts 仅以内部 ID 映射，没有运动类型、名称、起止时间。
本轮将已有运动按稳定顺序显示为“运动记录 1/2…”，只列该记录负荷、覆盖度与区间分钟，不展示内部 ID，不虚构类型、时间或时长；编号不表示发生顺序。
区间分钟指有心率观测的区间分钟，不能当总运动时长或全天覆盖。
目标沿用引擎结果；无目标显示“有效历史或当前准备度不足，暂无法生成参考区间”，不生成替代值。
基线和实际有效日沿用对应估算，夜间HRV与静息心率各按现有趋势含义和单位展示，不扩展生理推断。
睡眠详情使用报告分析日期，旧报告不标成昨晚；当前采样时间和报告生成时间分开。
不新增步数、距离、热量、血氧等读取类型，也不计算新评分。

### 4. 状态与可访问性

用户反馈睡眠页“顶部区域挡住内容”，布局修正为：状态内容直接作为SleepDetailView List的首个Section，而不是在列表外使用safeAreaInset顶部固定。滚动时状态随内容离开，不重复显示合成演示标记；不改变状态文本、刷新和数据规则。作为当前Build阶段的小型设计调整记录，不将用户反馈当作整体Gate3确认。
所有 Tab 共用真实/演示状态、固定分析时区、忙碌状态和报告修订。
每个主题页显示演示标识；退出后清掉演示专属详情路径，防止停留在合成详情。清除真实数据后旧详情不可继续展示旧报告。
空数据时各 Tab 仍可达，各页给对应缺失原因；健康连接仅由用户主动触发。刷新失败保留上次报告并显示失败状态。
刷新不重置 Tab、路径和趋势筛选；已过期估算沿用现有遮蔽策略，历史报告明确日期。
大字体使用纵向布局，VoiceOver读出标签、值、单位、日期、状态；减少动态效果沿用系统。

## Architecture
WristlabApp → 共享 DashboardModel → PhoneDashboardView(TabView) → 五个独立导航容器 → 现有报告展示与详情。
Views → DashboardModel → HealthRepository/HealthKitReader 的原有路径保持，视图不查询 HealthKit。
构建按原 Apple 脚本；真机只安装不内嵌Watch的临时手机工程，不提交签名配置。

## Risks / Trade-offs
| 风险 | 缓解 |
| --- | --- |
| 切换导致读取/状态重置 | 稳定Tab标识，独立路径/滚动位置，单实例model |
| 运动缺少元信息 | 展示已有摘要，明确编号含义，推迟类型/时间扩展 |
| 演示/清除后详情残留 | 共享报告且对来源变化清理不兼容路径 |
| 大字体内容增高 | 用内容分组而非固定像素高度验收 |
| 原生Tab可访问性回归 | 合成截图、VoiceOver与真机人工检查 |
